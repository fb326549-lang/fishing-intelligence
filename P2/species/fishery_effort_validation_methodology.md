# 台灣岸釣努力量與魚種權重驗證方法

## 目的

本文件只處理漁獵雷達三項指標及FCI權重所需的釣獲努力量驗證，不新增釣魚紀錄功能，也不把其他區域的CPUE直接套用到台灣東部。

## 1. 可用的官方資料與限制

### iOcean垂釣回報（海保署）

政府資料開放平台資料集157622為免費開放資料。公開資料字典列出：
- Fishing_Time（垂釣時間）
- People_Count（同行人數）
- WGS84X / WGS84Y（位置）
- Species_Name / Name_Code（魚種與學名代碼）
- Fishing_Count（尾數）
- Fishing_Length（體長）
- Type_Name（垂釣類型）

官方2024年《海洋漫波》第20期說明：垂釣時數及現場垂釣人數屬非必填欄位；若正確填寫，可用於估算垂釣努力量。這代表iOcean並非完全沒有努力量概念，但努力量欄位可能缺漏，且目前公開資料字典未明列垂釣時數欄位。正式使用前必須先檢查實際CSV/JSON原始欄位及非空比例，不得只憑資料集摘要推定已具備完整努力量。

官方2025年「垂釣回報執行與分析暨釣點漁獲食用安全調查計畫」資料集說明稱計畫建立科學調查與抽樣方法進行漁獲量推估。以下已依成果報告全文核對其計算單位、資料來源與東部樣本解析度；該方法只作總漁獲量估計與回報分布背景，不足以作本雷達的逐時生態反應或FCI權重。

#### 海保署成果報告抽樣方法核對

已讀取資料集175857所連結的海保署《垂釣回報執行與分析暨釣點漁獲食用安全調查計畫成果報告書》（方法見印刷頁8–10，回報統計見頁36–39）。報告以iOcean、巡查員及計畫調查員資料估計全台岸釣與船釣漁獲；岸釣按「同一釣點／日期／魚種」彙整漁獲重量，以每日回報次數作為平均值分母，再結合推估的釣客數及可垂釣日數推估月／季漁獲量。報告沒有把日內時數或人時作為岸釣分母，也沒有提供本模型所需的「四目標魚種 × 東部 × 時段 × 有效努力量 × 零漁獲」驗證樣本。氣象安全條件推估的可垂釣日數是調查量推估的一部分，不是魚種活動或生態適合度反應。

報告所述10,000筆回報統計按縣市及釣法分層：宜蘭1,354筆、花蓮64筆、臺東245筆（報告印刷頁37）。這些是全計畫回報列數，不能當作有效獨立作釣次數或努力量；縣市及釣法的漁獲重量表也不是四目標魚種的物種級東部反應曲線。此報告可作為台灣東部回報分布的低解析背景資料，不能解鎖三指標計分、FCI權重或逐時最佳時段。

#### 2026-11-11 原始CSV欄位稽核

直接讀取資料集157622連結的官方CSV（10,766,259 bytes；SHA-256 `f84002bcf856f3065e0f78c5dfc7a3cbd7c768333eb1b1ad3098d3ba17a82b09`；稽核日2026-11-11），共有76,435列物種回報、56,544個不同ID。這是全台資料集總量，不是東部目標魚種樣本數。實際欄位如下：

| 欄位 | 有值列 | 缺值列 | 解讀 |
|---|---:|---:|---|
| Fishing_Time | 76,435 | 0 | 全數為 `YYYY-MM-DD` 日期格式；沒有任何日內時間或垂釣時數。 |
| People_Count | 76,435 | 0 | 25,370列填0；欄位非空不代表可用人時，且仍須確認0的資料語意。 |
| WGS84X / WGS84Y | 各76,435 | 各0 | 有座標，但本次不據此推定目標魚種的東部逐時漁獲。 |
| Species_Name | 74,451 | 1,984 | 有缺少魚種名稱的列。 |
| Name_Code | 74,337 | 2,098 | 有缺少學名代碼的列；俗名及未鑑種資料不可升格為物種級反應。 |
| Fishing_Count | 75,734 | 701 | 701列空白；沒有明確記錄 `Fishing_Count=0` 的列。 |
| Fishing_Length | 76,430 | 5 | 體長不是垂釣努力量。 |

因此，公開CSV目前不含任何可分辨晨昏或逐時活動的垂釣時間，也沒有可辨識的零漁獲努力量對照；同行人數欄位雖全非空，但零值比例及缺少時數使其無法轉成人時CPUE。這份資料只能作回報物種／位置／日期的正向出現上下文，不能用於三項逐時指標、FCI權重校準、最佳活動時段或中魚率。不得將空白Fishing_Count當成零漁獲，也不得把日期欄轉成日內活動時間。

新增 `P2/species/audit_iocean_effort_data.py` 作為可重跑的離線欄位稽核工具，只輸出欄位完整度、日期／時間解析類別、空白／零／正漁獲列數、同行人數與時數欄位完整度及輸入檔雜湊；不輸出座標、不計算CPUE，也不會把資料升格為模型依據。執行：

```bash
python P2/species/audit_iocean_effort_data.py --input path/to/iocean_fishing_report.csv --out output/p2/iocean_effort_audit.json
```

`has_fields_for_person_hour_cpue_screen` 與 `has_fields_for_hourly_effort_screen` 只表示輸入資料有進一步審查所需的結構欄位，不代表努力量、零漁獲樣本或研究設計已通過科學驗證。

### 2. 官方現場抽樣研究可提供的努力量方法

**106年度墾丁國家公園海域垂釣魚類資源量監測調查（2）**
- 2017年調查10個公告測站及12個非公告垂釣區。
- 每季安排約兩週調查，每日分上午、下午兩梯次，每梯次每釣區約3–4小時。
- 共記錄5,080尾；報告明確採用「尾數／小時／人」或「公斤／小時／人」作為努力量單位。
- 2017年記錄到褐臭肚魚（Siganus fuscescens）200尾；另有舵魚屬（Kyphosus spp.）202尾。
- 舵魚僅鑑定到屬，不能當作南方舵魚K. bigibbus的物種級釣獲證據；墾丁資料亦不是台灣東部資料。
- 報告中的CPUE、努力量標準化與分季抽樣可作方法參考，但不可把該區域魚種數量或CPUE直接移植為東部模型權重。

**台灣北部港區垂釣行為研究（2013–2014）**
- 15處港區、73次抽樣調查、408份問卷。
- 整體平均漁獲率約1.37±2.99尾／小時／人，估計總努力量約522,515小時。
- 2,857尾樣本中，臭肚類約占65%（1,843尾）。
- 這是北部港區、特定抽樣與受訪者樣本，不能當作台灣東部岩岸CPUE；但可證明以人時標準化並結合現場抽樣估算休閒釣獲量是可行方法。

## 3. 本系統採用的標準化定義

若原始回報有可驗證的有效垂釣時數與人數：

\[
E_i=H_i\times P_i
\]

其中：
- \(H_i\)：第i筆／次有效垂釣時數（小時）
- \(P_i\)：實際參與垂釣人數
- \(E_i\)：人時努力量（angler-hours）

物種級尾數CPUE：

\[
CPUE_{s,r,t}=\frac{\sum CatchCount_{s,r,t}}{\sum E_{r,t}}
\]

物種級重量CPUE（只有體重資料可靠時）：

\[
CPUE^{kg}_{s,r,t}=\frac{\sum CatchWeight_{s,r,t}}{\sum E_{r,t}}
\]

計算前必須：
1. 魚種學名代碼通過鑑定；「白毛／舵魚屬」未鑑種資料不得併入南方舵魚。
2. 垂釣位置、時間、釣法、有效時數及人數可追溯。
3. 排除重複回報、時間不合理、位置不合理及無法辨識魚種資料。
4. 區分零漁獲努力量與未回報；沒有魚獲回報不能自動視為零漁獲。
5. 按海域、月份、時段、釣法及棲地分層；不得將不同區域或不同釣法直接合併。
6. 以獨立日期／釣點留出驗證，避免同一釣友或同一趟釣遊同時進入訓練與驗證資料。

## 4. 東部魚情模型的使用門檻

- **可作背景：** 官方開放回報的正向魚種、時間及位置分布；外地CPUE研究的抽樣設計與計算方法。
- **可作校準：** 台灣東部、物種級鑑定、有效人時努力量完整、且包含零漁獲／未中魚時段的資料。
- **不可作校準：** 只有正向魚獲照片或尾數、沒有努力量；把Fishing_Time日期欄位誤當垂釣時數；把屬級Kyphosus spp.當成K. bigibbus；把墾丁或北部港區CPUE當作台東／花蓮CPUE。

目前iOcean原始CSV及海保署成果報告方法稽核已完成：公開CSV沒有日內時數與零漁獲對照；成果報告使用每日回報數與估計可垂釣日數推估總漁獲，沒有本模型所需的人時及逐時魚種反應驗證資料。若要解除限制，仍需建立或取得具標準化東部釣點／時段抽樣、物種鑑定、人時努力量及零漁獲紀錄的資料；在此之前，FCI權重、三項指標正式逐時分數及最佳活動時段維持未核准。
